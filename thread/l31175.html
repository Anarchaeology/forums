Server Monitor Tools
Server Monitor Agent

A lot of people have written their own server monitors, and have been connecting to our game servers directly.
This has caused a lot of unwanted traffic to our login handlers and game servers.

We can now offer a centralized agent that collects all this information for you, and publishes it in a single XML file.

We encourage server monitor tool developers to connect to this agent instead of polling the servers directly.
We have been in touch with the developers of some of the most popular server monitors, and we will link to them from this web site as soon as their tools are ready.

If you want to develop your own server monitor tool, look below for documentation.

We hope that our the excellent developers in our community will value this and we will try to provide even more interesting information as time goes by.


DOCUMENTATION
-------------


Server Monitor Agent

This is a short description about the xml file published by the server monitor agent: http://probes.funcom.com/ao.xml

You can read the syntax from the file. I will comment on it below, but first: Some terminology:

What many refer to as "server" - i.e. the machine farm, software and additional networking hardware that is required to run one dimension of the game, is what we refer to as an "Anarchy Online Dimension". There are currenlty only two dimensions: The Live dimension and the Beta/Test dimension.

What we call a "Server", is a process that runs one or more

"Playfields". What you will see in this xml file is a list of most of the "Static Playfields" that make up the "static" world in a dimension of AO. One of these playfields, let's say Avalon, can be set up to run on one machine that also runs other playfields, so if Avalon is slow, it might be
because some other playfield is overloaded. Then we have the "Dynamic Playfields" or "Virtual Playfields". These are shifted from server to server to do load balancing. So it doesn't make sense for you to monitor these. These are
playfields like shops, dungeons, character creation and the like. Ok, about the file format:

servermanager, status=0 or 1

0=down, 1=up

The server manager is required for changing playfields ("zoning").

clientmanager, status=0 or 1

0=down, 1=up.

The client manager(s) are required for the
initial connection (login).

chatserver, status=0 or 1

0=down, 1=up

playfield, id, name, status=0 or 1

I'm not sure if you want to use the id. This corresponds to a value that the players can see in the game when they press F9. You will probably want to use the name instead.

Status is 0 or 1. But it doesn't mean "down" or "up"! 1 means that the playfield is running. (And we might add more status' later.) 0 means that the playfield is *not active*, which is different from being down. The way it works is that one physical machine runs one or more game servers.

Each game server is set up to run one or more playfields. If there are no players on a playfield, it will either not be started, or it will eventually time out and go back "to sleep". This list only has static playfields, for the
reason I mentioned above. Please make sure that you don't refer to status=0 as a playfield being "down", but as "inactive".

distribution, onlinecharacters, affiliation

This shows the percentage distribution of players that are online: clan, neutral or omni.

message type="status" or "news"

These are one-liners. A status message could be "Down for server patch", a news message could be "Riot in Tir".
