The problem seems to be a conflict between the weilded weapon (which has a static QL) and fists, which have dynamic QL's. When your numbers change, your fists QL changes. Weapons weilded override fists when fists change. Thus unequipping and changing the numbers works.

If they'd put in conditional when the server does a weapons parse like this one:

If fist's QL > weapon weilded's QL use fist's QL else use weapon weilded's QL.

That way an MA, who's fists QL is always goingt to be higher than the weapons QL will always punch.

The problem would be solved. It's THAT easy! =)


The real problem, I speculate, is that FC never properly implemented the ability to punch and weild weapons at the same time. There's a bunch of code for multi-weild that probably gets fubared. Who knows. hehe. Not FC.
