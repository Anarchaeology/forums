Priorities?
It's been stated over and over again that Funcom's overwhelming priority is to fix exploits. What I'd like to know is what percentage of the developers available cycles are being used, if any, to fix bugs and make overall optimizations to the software?
In every development shop that I've worked for, application performance is one of the highest priorities, right next to bug squashing. New features usually rate lower, just because there is no use giving your users new functionality if the old features don't work right.
I'm not sure if it's because of the development houses building these massively multiplayer online games or if it's the player community as whole that is responsible for these inverted priorities. In the corporate world there is a much lower tolerance for defects in software then in the gaming world. Where else but in the gaming world will you find user defending a product that doesn't 100% do what it's supposed to do. In fact in the gaming world users that voice concerns, either strongly or moderately, are usually flamed by hordes of banner touting zealots, bent on purging the heretics from the World.
The air of tolerance in the game community has, in my opinion, has bread an attitude in game producers that it's alright to forego quality for the sake quantity. Fortunately this is not the case for all game developers, a precious few still try to put quality first, like Blizzard, Westwood, and more recently the creators of DAoC. I'm not a fanboy for DAoC, I've never played the game but 200,000+ copies and an almost flawless launch is a new benchmark that hopefully all other game producers will try to measure up to.
With games like Everquest, WWII Online, 10Six and AO having a somewhat troubled beginning I would think that developers like Funcom would be doing their best to shake the stigma that is attached to AO, by improving the core product. I think if Funcom is worried about make the most customers happy, why not remove/improve the things that give users the most grief, bugs.
This is just my two cents worth. I hope that most will take this post in the context that it was intended and not as AO flame.

One thing many people do not seem to realize...

A development team is rarely a uniform group of people with the same skills, working on the same parts of a system.

You usually have sub-teams working on different parts of the game. Now some of these teams working with, say, user interface stuff like the added support for japanese input methods, might finish their project ahead of those working with bugs in the game core.

This has nothing to do with priorities, but simply what parts get done first...

Which makes all these people screaming about certain things being fixed before others seem a bit silly...

Would you rather have those specialized programmers sit twiddle their thumbs waiting for the others to finish the "important" bugs first ?
