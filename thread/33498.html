Pet pathing solution: Pre-defined waypoints
It is a simple concept. Have all the pets (and NPCs) follow pre-defined waypoints. Essentially, when a room is made for a mission or indoor area, there is a waypoint system layed out that the pets can follow on sort of a railroad like method. Sure it may not look great, but it is a start. The waypoints could be set up so in order to get from one to another, the pet might be able to go straight to it depending on the setup, or go through several waypoints to get to the destination. In order for the bot to go to the next waypoint, the pet owner would activate the waypoints by walking over them. That would indicate to the pet to go there.

Not sure how the coding could work, but it could be set up so that the pet would go through all the waypoints the owner hit in order, or just head to the last waypoint the owner hit.

Since the outdoor areas are so huge, placing waypoints all over would take way too much time. Instead the pets can still use the same free-roaming method and dynamic waypoint system the pets currently use. However, should the pet encounter an obstacle, there could be a set of waypoints going around the obstacle that would allow the pet to navigate around it, then be released and continue on its way.

Something like this would probably be a great improvement over what we have now, but we should still get our much wanted /pet warp command just as a back-up.

Waypoints might work...
But, there is a better, well tested, public availible and fast way of doing pet pathing.

WARNING Solution to path problems enclosed, Might take some experience in development to read... (cz, dont even bother trying )

its called A* (pronounced "A-star").

This heuristic search ranks each node by an estimate of the best route that goes through that node. The typical formula is expressed as:

code:
(n) = g(n) + h(n)

where:

f(n)    is the score assigned to node n 

g(n)    is the actual cheapest cost of 

        arriving at n from the start 

h(n)    is the heuristic estimate of the 

         cost to the goal from n

ok, over to some code..

code:
	s.g = 0		// s is the start node
	s.h = GoalDistEstimate( s )
	s.f = s.g + s.h
	s.parent = null
	push s on Open
	while Open is not empty
		pop node n from Open  // n has the lowest f
		if n is a goal node 
			construct path 
			return success
		for each successor n' of n
			newg = n.g + cost(n,n')
			if n' is in Open or Closed,
			 and n'.g <= newg
				skip
			n'.parent = n
			n'.g = newg
			n'.h = GoalDistEstimate( n' )
			n'.f = n'.g + n'.h
			if n' is in Closed
				remove it from Closed
			if n' is not yet in Open
				push n' on Open
		push n onto Closed
	return failure  // if no path found
-------------

EDIT: A small image to show the logic in action
Might help to clear things up
the black areas is walls, and the Grayish are different levels of obstacles.. the darker they are ,the higher the movement cost.

A* has a couple interesting properties. It is guaranteed to find the shortest , or the fastest if the map has movement cost, as long as the heuristic estimate, h(n), is admissible-that is, it is never greater than the true remaining distance to the goal. It makes the most efficient use of the heuristic function: no search that uses the same heuristic function h(n) and finds optimal paths will expand fewer nodes than A*, not counting tie-breaking among nodes of equal cost.

Using A* would solve most (all?) of the INDOOR pathing problems

for outdoor, other systems might work better, like one called 'Dijkstra's algorithm' (also public availible)
