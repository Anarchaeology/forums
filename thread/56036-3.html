Proxies? How?
quote:
Originally posted by Animosity
"Also I noticed in a different post you mention adding proxy servers in metro areas. How do you expect these to speed up content that is changing every millisecond. Normal proxy servers speed up access because they can cache static content hence you don't need to rely on the server side server for all of the page, but how can this work on VERY dynamic content? As far as I know the static graphics in the game are stored locally on the client side."

Having sold, design, and maintained this type of equipment, I am a strong believer in a distributed, proxied environment. As you bring the servers closer to the end nodes, the difference between server and client maintained data diminishes dramatically. If FC made it that every twitch of an NPC is dictated from a centralized server, well, That would be one of my first recommendations to optimize.
I am sorry, but I don't see any answer to the question here. Only a verbose description of how you happen to believe a proxy environment is a "good thing".

How does the second-by-second dynamically changing environment get passed back, first through your proxy and then back to the central systsm, then distributed amongst the proxys? How do the frequent and rapid client-initiated "updates" to the basically real-time common shared environment get efficiently re-distributed amongst all those proxies and then back down to the proxied clients?

You really haven't addressed the issue you have so casually thrown out into the forum. It's easy to know a few buzzwords and toss them around. But where is the beef?
