Roleplaying Content: Something to write on!
The following is an excerpt from a short talk I gave at the OOC Roleplayers Conference on RK1 today. I would appreciate your feedback.

* * * * * * * * * * * * * * * * * * * * * * * * * * * * * *

Hello. I am Szentasha of Unity of the Rose. Thank you for coming today. I hope you find this topic interesting.

I would like to speak with you today about the need for more roleplaying content and features in Anarchy Online, and to present, for your consideration, the concept of a new game feature that I feel would greatly empower roleplayers in this game.

I'd like to start by saying that although I am sure many of you would disagree with me. I do not feel that the 'story' that Funcom has provided us does do much to encourage roleplaying in this game. The few story-related events that occur within the game either involve so many people that it makes it difficult for a single person to feel engaged .. or only a few select people, leaving the rest of us out of the picture.

My feeling is that most rewarding roleplaying experiences in this game will come from small-scale scenarios and events, conceived and run by the players.

To their credit, Funcom has provided us a beautiful setting where these events can take place. But many players who are interested in organizing roleplaying events quickly realize the limitations of roleplaying content and features in this game. This is one reason why the same roleplaying themes are being reused .. a dance party, a race, a rally..

There are many wonderful ideas about how to make improvements in this area. However, I would like to suggest that the one new game feature that would greatly empower the roleplaying community is the same foundation many classic roleplaying games are based on .. a piece of paper that you can write something on and hand to another player.

This is a very simple concept, but it would dramatically expand the possibilities of roleplaying. Each piece of paper could be a clue, directions, a love letter, or represent an object in a roleplaying scenario. Players could use these objects to help run roleplaying events.

There are many issues associated with these objects .. that of storage of the dynamic text information, over duplication of the objects, and authentication.. but I feel that there are reasonable solutions to these problems.

I won't get into these details now, but would be happy to discuss these details upon request..

I have started a thread on the Funcom forums in the 'Envisioned' section with the contents of this discussion titled 'Roleplaying Content: Something to write on!' The forums are flooded with requests for bug fixes, changes in game mechanics, profession balancing .. all of these issues are important.. but the voice of roleplayers can barely be heard through the clutter. If issues of interest to the roleplaying community are going to be noticed and acted upon by Funcom, we must make our voices heard on the forums. If you can, please take the time to respond to my thread, and start threads of your own on roleplaying topics that you care about.

Thank you all.

I've had my ideas and I've read your ideas. I think I have a solution. It is complicated but right up our alley.

This is obviously the digital age and lets keep it that way. I suggest that FC comes up with a computer platform chip that we can buy. A digital chip that stores data. The chip should be equipt in our computer platforms. While the chip is in installed we should be able to:

Make Folders
Make data files we can type in.
Be able to copy the files or folders made.

When the description window is up it should say somthing like this " This is the RJ/12 Digital storage chip. It can store X amount of data. After that there should be some icons to click on.
<Make Folder> <Make File> <Copy File> <Delete File> <Back>

Make folder- Will do just that. Create a folder. Double click the folder and the description window have the 5 types of icons to choose.

Make file- Will create a blank file. Blank window except a close button and a cursor ready for you to use.

Delete File- Highlight the File/Folder click on delete. A yes or no prompt pops up, choose yes.

Back- Takes you back to a previous window.

It should also show the files and folders in the main window.

To copy to another chip you must have at least one other chip installed to do so. Maximum data chips installed depends on the amount of slots in your computer platform. All you need to do is highlight the file or folder to be copied and click on the copy icon. If more than one data chip is installed then a window would pop up asking "which chip should the file be copied to" or "ALL".
The file will then be sent to the chip(s) in your computer platform. If no other chip is installed the game should promp you to install one.

Unless there was a icon for copywrite which might allow the original writer to make a copy of a tradeable master, the copy is then transfered to another chip only then making it NODROP/NOTRADE status.

The data chip should equip and unequip faster than all the other belt components. For the ease of the digital age and our patience.

Good idea
I think your idea is a good one .. very contemporary. My comments are this:

- Having this information reside in a chip is a great idea, and more modern than paper. This would be acceptable to me .
- There could be separate devices for writing and copying these chips.
- There is no reason to have a folder structure, sets of files would be fine.
- From a programmers perspective, most objects in the game are fixed objects (not variable). This is what is different about this concept, is that you can have two different objects of the same type that have different persisted states. Also, having an object with multiple "files" in it is more of a composite object, and will probably also be difficult for them. It also makes it difficult to select or specify files to operate on. My feeling is that is would be more than adequate for each chip to have a single stream of data one it (one file).
- Also, maybe there should be a device used to read the chips.
- Strange idea: assume that chip data is encrypted. Have the chip aquire the QL of the writer used to burn the chip, and make it so that you need to have a reader/copier of at least the QL in order to read the data.

Thanks for responding to this thread, Grimmtooth!
