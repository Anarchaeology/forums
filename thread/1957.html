Good point
I hadn't thought about sending tells.

They would have to have a row in the DB for the character's starting server (where the character was created). Instead of having me rename my character when I moved, they could append or prepend my nickname with the server ID.

Skara is my name on RK1, so if I travelled to RK2:

Skara-[RK2]

As soon as I moved back to RK1, the RK2 would be dropped.

If a Skara from RK2 moved to RK1, the RK2 would show up whether I was on RK1 or not.

That way all characters would always be unique, and no one could trash the name of another character.

Also, you wouldn't need to rename when you returned to your home server because a character with the same name from the other server was now on your home server.

Anyone on RK1 wanting to send tells to my RK1 Skara would just /tell Skara (them being notified which server I was on could be optional), and it would be routed. Anyone on RK2 that wanted to talk to my RK1 Skara while visiting RK2 would need to /tell Skara-[RK2].
