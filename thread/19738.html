On data integrity and lost items
Scenario :

Player A needs implants assembled.
Player A gives them to Player B
Player B gets disconnected
Player B reconnects
Player B does not have the items Player A just gave him. zoning does not help
Player A gets very frustrated
Player B risks accusations of theft

Both player inventories are server side. Most likely in a database.

On a decent database with transaction support ( pseudocode ) :

BEGIN TRANSACTION playertrade
if INSERT PLAYERB item
if DELETE FROM PLAYERA item
Result = OK
else
Result = DeleteFailed
else
Result = InsertFailed

if Result = OK
COMMIT TRANSACTION playertrade
else
ROLLBACK TRANSACTION playertrade

This basically ensures that if Player B never got the items saved into his inventory ( assuming that data in the database do not spontaneously disappear on client disconnect ), the transaction is "undone", pretending nothing ever happened.

So if something goes wrong, Players A and B will suffer no loss of cash or items...just a nagging feeling of Deja Vu...
