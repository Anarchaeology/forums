The problems with scripts in AO
1. You can call another script from within a script (will give error message if the second script isn't found) but it will not execute any commands in the second script

Nice command, not hard to finish implimenting, how could a programmer not like recursive scripting?

2. Key strokes in the script are not processed by the command interface. If you have a script with only "x" in it, you will not sit down when executing the script.

A real finger saver here, as an MP I buff up about 11 nanos before I'm ready for combat and thats every 30 minutes. Very annoying, if you allow commands to be executed correctly, I could script it.

An easier solution, and still a nice one would be a new script command.

/run1,3 for the 1st shortcut bar and do the 3'd thing on it.

I'd also like a /sit /stand for that so I could have it buff me and renano while I get more soda

3. Arguments passed to scripts are not observing quotation boundries. ie:

/pet bobo %1 %2

When you pass
/script chat "Hello there!"

Executes

bobo: Hello

This ones a RP one for now, only real use is people who want to get thier pets chating. There shouldn't be a reason to have a seperate script just for chatting and it wouldn't be required if this were processed correctly.

4. I'd have to do more testing, but I'm pretty sure they script system is not waiting for the execution of one item before moving on to the next.

/selectself
/pet heal

Sometimes ends up with the healer healing the original target instead of me.

I can always delay it if I have to, but the script would have better reliability if AO didn't process the second command until the 1st had executed completely.
